# Implemented API contract

Go/Fiber API and React frontend implement the endpoints below. Storage is MongoDB with replica-set transactions. Visual brand is TAMAK, matching the supplied blue/coral reference. Monetary values are KGS minor units.

Application: Koffe, Russian interface, currency KGS. All monetary values are integer minor units (100 = 1 сом). Backend module `koffe/api`. JSON fields camelCase, Mongo IDs exposed as `id` strings. Date values ISO 8601. REST response is bare object or bare array, errors `{ "error": "human readable message", "code": "machine_code" }`. All list endpoints return arrays (bounded, support `limit` and `offset`).

Auth: POST /api/auth/login {login,password} and POST /api/auth/refresh -> {accessToken,user}; HttpOnly refresh cookie; GET /api/auth/me -> User; POST /api/auth/logout -> {ok:true}; PATCH /api/auth/password {currentPassword,newPassword}. User {id,name,login,role,isActive,createdAt,updatedAt}. GET lists require Bearer access JWT. Admin manages configuration and reads orders. Cashier routes require cashier; admin cannot mark delivery or payment. Frontend stores access token only in memory, refresh on startup and one retry after 401.

GET /api/public/menu/:tableToken -> {table,categories,products}; GET /api/public/categories -> Category[]; GET /api/public/products -> Product[]. Table {id,number,isActive,status,createdAt,updatedAt}; Category {id,name,sortOrder,isActive}; Product {id,categoryId,name,description,imageUrl,price,preparationTime,isAvailable}. Public menu validates HMAC signed token and DB tokenHash. Admin GET /api/admin/categories and /api/admin/products list all (including disabled), POST creates, PATCH /:id edits, DELETE /:id soft-deactivates.

POST /api/public/orders with Idempotency-Key header (UUID) and {tableToken,items:[{productId,quantity}],customerComment} -> Order (201 first, 200 replay); GET /api/public/orders/:publicToken -> Order; POST /api/public/orders/:publicToken/cancel -> Order. Order {id,publicToken,orderNumber,tableId,tableNumber,tableSessionId,items:[{productId,productNameSnapshot,priceSnapshot,quantity,subtotal}],totalPrice,status,estimatedMinutes,customerComment,paymentStatus,expiresAt?,createdAt,updatedAt}. publicToken is a random bearer capability. Replayed idempotency request with different payload -> 409.

GET /api/admin/dashboard -> {revenueToday,ordersToday,activeOrders,averageOrder,occupiedTables,totalTables,recentOrders:Order[],popularProducts:[{name,quantity,revenue}],dailyRevenue:[{date,revenue,orders}]}.
GET /api/admin/employees -> User[]; POST {name,login,password,role:cashier}; PATCH /:id {name?,role?,isActive?,password?}; DELETE /:id soft-block.
GET /api/admin/tables -> Table[]; POST {number} -> Table; PATCH /:id {number?,isActive?}; POST /:id/qr -> {tableToken,url} rotates/revokes old QR; GET /api/cashier/tables -> Table[].
GET /api/admin/orders and /api/cashier/orders -> Order[], optional ?status=...
POST /api/cashier/orders/:id/confirm or /accept {estimatedMinutes,presenceConfirmed:true} pending_confirmation -> accepted (both aliases perform presence confirmation). POST /reject {reason?} pending_confirmation|accepted -> cancelled; POST /preparing accepted -> preparing; POST /ready preparing -> ready; POST /delivering ready -> delivering; POST /deliver ready|delivering -> delivered; POST /pay {paymentConfirmed:true} delivered -> paid.
GET /api/admin/audit-log -> {id,userId,action,entity,entityId,metadata,createdAt}[] (no secrets).

WebSocket `/ws` on SAME application port as API. coder/websocket via net/http plus Fiber v3 adaptor for /api. Client sends first frame {type:"authenticate",accessToken} OR {type:"authenticate",publicToken}. Server replies {type:"connected"}. Events {type:"order.created"|"order.pending_confirmation"|"order.accepted"|"order.preparing"|"order.ready"|"order.delivering"|"order.delivered"|"order.paid"|"order.cancelled"|"table.updated"|"menu.updated"|"notification.created",data:...}. Server scopes public events to own order, cashier/admin appropriately. Access token expiry closes socket (client refresh/reconnect); heartbeat and bounded writes. Frontend invalidates matching TanStack queries on events, polling as recovery.

Server starts with --seed flag OR separate cmd/seed. Demo users admin,cashier / ChangeMe123!, seeded categories/products/tables with real Mongo storage. No mock fallback. GET /healthz liveness, /readyz Mongo readiness. Swagger /swagger (and /docs) and spec /openapi.json. Config .env via process env. Single Mongo connection pool, transactions require replica set. Deadline field `expiresAt` stays historical on orders (normal index); TTL ONLY on temporary `order_expirations` and `refresh_sessions` records; job queries pending orders deadlines and atomically cancels even after restart.

Frontend Vite :5173 proxies /api,/ws to :8080. Current staff screens: /login,/admin,/admin/menu,/admin/tables,/admin/employees,/admin/orders,/admin/audit,/admin/settings. Cashier screens: /cashier, /cashier/tables, /cashier/settings. Public /menu (browse only), /menu/table/:tableToken and /orders/:publicToken. Root redirects /menu. TAMAK visual design matches the supplied image: white surfaces, blue actions, pale lavender panels, coral accents, Lucide icons, mobile usable. Development-only /preview/admin contains no mock business records, sends no API calls and disables mutations; it is absent from production. PWA caches the app shell only, never API/private/order responses, and never silently queues orders offline.
